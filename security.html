Canvas OAuth security & privacy summary

GPAce · September 2026 · Not a personal access token request

GPAce is a student GPA tracker for iOS and Android (gpaceapp.org). Students do not create a GPAce account. This note describes a read-only Canvas OAuth Developer Key: one app registration so a student can authorize their own Canvas login. We are not asking the institution to issue tokens to the developer or to any student. Providing this information does not guarantee approval. GPAce is independently operated, not an institutionally supported integration.

Access model

  • The student signs in with their own school Canvas / SSO credentials on Canvas’s login page.
  • The resulting token is limited to that student. GPAce cannot see other students’ records.
  • No write, delete, admin, masquerade, or SIS provisioning scopes.
  • The student can disconnect in the app or revoke the app in Canvas (Account → Settings). The school can disable the Developer Key at any time.

Requested Canvas scopes (GET only)

  • url:GET|/api/v1/users/:user_id/profile
  • url:GET|/api/v1/courses
  • url:GET|/api/v1/courses/:id
  • url:GET|/api/v1/courses/:course_id/assignment_groups
  • url:GET|/api/v1/courses/:course_id/assignments

Paste these five scopes. Do not use Canvas’s “Read only” checkbox (that grants every GET endpoint). GPAce sends the same five scopes in the OAuth request.

Not in scope

  • Posting, editing, or deleting grades or content
  • Instructor or admin roles
  • Other users’ accounts or gradebooks
  • LTI placement inside Canvas courses
  • Advertising or sale of academic data

Allow Include Parameters (required for grades)

Please enable Allow Include Parameters on the key. GPAce does not call extra endpoints for scores. It uses include[] on the endpoints above so the authorizing student can see their own enrollment totals and assignment submissions (include[]=term, total_scores, enrollments, course_image on courses; include[]=submission on assignments). On a scoped key, Canvas ignores include[] unless that box is on. Without it, OAuth can succeed and grades will not sync.

Where data is stored

  • Grades and course data stay on the student’s device. GPAce does not operate a grade database or student profile store.
  • OAuth tokens are stored on device (iOS/Android secure storage). The GPAce backend holds the Developer Key client secret (it cannot live in the mobile app) and exchanges the authorization code / refresh token with Canvas. Tokens are returned to the device and are not written to a GPAce database.
  • After login, iOS and Android fetch courses and grades directly from Canvas. Token refresh still goes through the GPAce backend. Grade JSON does not.
  • Optional school-search analytics record query text and selected school id only — not names, tokens, or grades.
  • In-app purchases go through Apple or Google and RevenueCat. Payment processors never receive Canvas credentials or gradebooks.

OAuth configuration

Redirect URI (register on the Developer Key): https://gpace-api.onrender.com/auth/canvas/callback

App return (allowlisted): gpace://

Hosting is a Node.js service on Render. The backend only completes the OAuth redirect to the GPAce app scheme. It will not hand an authorization code to an arbitrary URL. Application code does not log tokens or grade payloads. The hosting provider could still have its own request logs.

Long-term ownership

GPAce is independently operated by Kai Greenberg. There is no vendor contract, SLA, or SOC 2 report. Support: support@gpaceapp.org. If the school later wants the integration gone, disable the Developer Key in Canvas. If GPAce is no longer maintained, the school should disable the key; local grades already on a student’s phone stay on that phone until deleted.
